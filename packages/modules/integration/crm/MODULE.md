# integration/crm

**Owns:** schema `crm.*` — mirror (read-only projection: crm_client_id PK, email_normalized UNIQUE, route_history, advisor, deleted_at soft-delete), sync_runs.
**Publishes:** `crm.mirror.synced` (one per run), `crm.activity_created` (noConsumer).
**Consumes:** none in this branch (`offer.responded` retired; `member.deleted` activity is stage 5).
**Ports (defines):** `CRMConnector { findByEmail, createActivity, submitRequest }` — every outbound call is `AbortSignal.timeout(5000)` and surfaces `CrmTimeoutError` on abort. A failure carries `retryable` (`CrmFailure`, api): false — the CRM refused the request as it is — and `send-requests` gives the request up at once; anything else is tried again (ADR-IMPL-065). Adapters: `email` (Postmark to `OPERATORS_EMAIL`), `http` (ADR-IMPL-065), `mock` (tests/dev, staging).
**Facade:** `findByEmail(emailNormalized)` (members), `submitRequest` (requests module). Mirror/freshness stay stage 5.
**Jobs:** none registered (`crmModule` returns `jobs: []`; `POST /v1/internal/run/<job>` answers 404 for each). Planned and not built (stage 5, ADR-IMPL-021): `sync-mirror` (nightly 03:00 + on demand: one read-only SELECT, upsert batches of 5000, soft-delete, sync_runs), `reconcile-activities` (15 min: unsynced > 10 min by external_id), `waitlist-recheck` — not built.
**Request e-mail (`email` adapter):** `CrmRequestPayload` (api) is what `send-requests` hands over; past the trip and the contact every field is optional, so `mock` and other adapters keep working. The operator's e-mail opens `New quote|alternative|offer|fare request R-…`, names the fare (`Fare <id> — British Airways — $4,200 (published $7,850, Sabre · 16 Sep)`) or the offer (`Offer <title> — <id> — $3,900`) only with what the request recorded, and a resend (`_attempt` > 1: a send that timed out may have delivered the first copy) says so — the subject starts `Resent (attempt n) — may duplicate:` and the text `If R-… already reached you, ignore this copy.`; the reference is the key the copies share.
**Request over http (`http` adapter, ADR-IMPL-065):** `CRM_API_URL` (https; http only to localhost, outside production; in production a public address, never a loopback, private or link-local one; no credentials in it) and `CRM_API_SECRET` (at least 32 characters), both required — `loadEnv` refuses `CRM_ADAPTER=http` without them. `submitRequest` POSTs the `CrmRequestPayload` as JSON without `_actions` and `_attempt` (the e-mail's links; a resend is then the same body), with `Idempotency-Key: <reference>`, `X-BBC-Timestamp` (Unix seconds) and `X-BBC-Signature` (hex HMAC-SHA256 of `<timestamp>.<body>` keyed with the secret's text as UTF-8, never decoded; the body's `reference` equals the key, so the CRM can refuse a call where they differ), within 5 s; a redirect is not followed. A 2xx gives `crmRequestId` `http:<reference>`. A timeout, a network error (`CrmUnreachableError`), 408, 429 and 5xx are retryable; any other status is permanent (`CrmHttpError`); a request without a reference is never sent (`CrmRequestInvalidError`). Errors name the call and the status only; the answer's body is never read and nothing is logged. `findByEmail` answers null and `createActivity` `{ id: null }`, without a call: the lookup runs inside the profile's insert at sign-up, and matching is the mirror's job. The CRM reports a status through requests' `POST /v1/internal/requests/:id/status` (`_request_id`, `X-Internal-Secret` today; `INTERNAL_API_SECRET` unlocks every system permission, so the CRM needs a credential of its own scoped to `requests:update-any` before go-live — ADR-IMPL-065).
**Out of scope:** writing anything to the CRM but a request (`submitRequest`: the `http` adapter's one POST per request, ADR-IMPL-065) and activities (`createActivity`, stage 5); CRM schema knowledge outside the single sync SELECT.
**Invariants tested:** CRM down → delivery retried, activity created exactly once after recovery (external_id) · sync failure at batch k leaves batches < k consistent and run failed · soft-delete never hard-deletes · freshness derived from last succeeded run · http, against a fake CRM: the signature verifies with the secret and not with another (the ADR's vectors, the key never decoded), Idempotency-Key is the reference and a resend sends the same key and body, a hanging CRM is a retryable timeout at the call's ceiling, 408/429/5xx and an unreachable CRM are retryable, other 4xx and a redirect permanent (not followed), no body, secret or member's detail in an error, no call for `findByEmail` · env: http needs both settings, a short or commented-out secret is refused, https only (http to localhost outside production), in production no loopback, private or link-local address, no credentials in the address.
