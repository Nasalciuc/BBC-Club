# integration/email

**Owns:** nothing in the database.
**Publishes:** none.
**Consumes:** none.
**Ports (implements):** `EmailFacade` (`src/api/types.ts`) — `sendOtp({ to, otp, purpose })` and `sendOperatorRequest({ to, subject, text, replyTo? })`; both resolve only once the provider accepted the message and throw on any failure. Two senders: `postmarkSender` (Postmark's `/email` API, `MessageStream: "outbound"`) when `POSTMARK_SERVER_TOKEN` is set, `consoleSender` otherwise. No SES sender exists. Tests replace it through `emailModule(override)` (the capturing sender lives in `apps/api/test/helpers/capturing-email.ts`, not here).
**Facade:** `@bbc/email` — the types `EmailFacade` and `OtpPurpose`, `postmarkSender({ token, from, fetchImpl?, timeoutMs? })`, `consoleSender(log?)`, `POSTMARK_TIMEOUT_MS`, `rememberDevOtp` / `lastDevOtp(email)` (an in-memory last code per address, lower-cased, for `GET /v1/test/last-otp`, which the API mounts only outside production); `@bbc/email/module` — `emailModule(override?)`.
**Env:** `POSTMARK_SERVER_TOKEN` (optional in development, where codes go to the console; `loadEnv()` refuses to boot production without it, so the console sender never reaches a member) · `POSTMARK_FROM` (the sender address, defaulted). The operators' address (`OPERATORS_EMAIL`) is the crm module's, passed in as `to`.
**What is sent when:** a sign-in, verification, reset or change-email code when identity's emailOTP callback has claimed the send (a resend inside the cooldown sends nothing) — plain text `Your code is … It expires in 15 minutes.`, the subject per `OtpPurpose`, `Tag` = the purpose; a request to the specialists when crm's `email` adapter submits it from the `send-requests` job — its subject and text are crm's, `ReplyTo` the member's address.
**Failures and retries:** no retry here. Every call is abandoned after `POSTMARK_TIMEOUT_MS` (4 s, `AbortSignal.timeout`: a `TimeoutError`); a non-2xx throws `Postmark <status>: <first 200 characters of the answer>`. Identity releases the OTP claim so the member can ask again (a sign-in send answers 503 `EMAIL_UNDELIVERABLE`); the request job retries the operator mail, which crm marks as a possible duplicate.
**Logging:** never the code, never the mail body. The console sender logs `[dev-email] <purpose> → <address>` for a code and the subject for a request; the Postmark error text can name the address, so identity logs a failed send by its facts only (purpose, reason, status, Postmark error code).
**Out of scope:** marketing email, HTML templates (v2: React Email).
**Invariants tested:** recipient = input.to and the code in the body, a rejection throws `Postmark <status>` (`identity/tests/email.test.ts`) · the operator mail carries To, ReplyTo, subject, text and the outbound stream (`tests/operator-request.test.ts`) · a hung Postmark fails both sends with `TimeoutError` (`tests/timeout.test.ts`) · production without a token refuses to boot (`scripts/check-env.test.ts`) · `/v1/test/last-otp` absent in production (`apps/api/test/last-otp.test.ts`). The subject per purpose is not tested.
