# domain/proposals

**Owns:** schema `proposals.*` — offers (idempotency_key UNIQUE, source, targeting XOR target_member_id, route, cabin, price/published_price, flight_facts, rating, validity, status), offer_targets (segment fan-out, PK offer+member).
**Rating** (ADR-IMPL-056, 0032): `offers.rating numeric(2,1)`, the rating the offer's cards print beside the city (02, 16: `★ 4.8`) — given by the sender in the ingest's optional `rating` (a number from 1 to 5, one decimal place at most), never computed here; null without one. The BFF's `ProposalCardVM.rating` (and so the detail's, Home's and the feed's cards) reads it as a number, null when absent.
**Publishes:** `offer.published` (same tx as insert), `offer.expired`, `offer.withdrawn`.
**Consumes:** `personalization.candidate_accepted` (v2) → publish. `member.deleted` → delete `offer_targets` for that member.
**Ports:** none (S2S ingestion is a route in this module, guarded by `proposals:ingest`).
**Facade:** `feed(actor, cursor)`, `getVisible(actor, offerId)` (null → 404 upstream), `verdict(actor, offerId)` — what the offer is to the member, one read (ADR-IMPL-075): `visible`; `gone` (withdrawn, expired or past its validity, and it was theirs: everyone's, theirs, their segment's — 410, and a request made from it goes through); `not_yours` (someone else's or not yet published — 404); `missing` — `getAny(offerId)` (system/operator), `ingest(input, idempotencyKey)`, `withdraw(offerId, reason)`. A write to `offers` or `offer_targets` bumps `proposals.offers` (0047), so Home and the feed tell before reading that a member's offers did not change. The feed's first page and the verdict are built once per executor (ADR-IMPL-074); `status = 'active'` is a literal in the SQL, so the expire job's `offers_expiry` (partial on it) matches on the generic plan.
**Jobs:** `expire-offers` (every 5 min: active & valid_until < now → expired + event).
**Out of scope:** pricing logic, booking, GDS lookups, request-a-proposal (`domain/requests`, decision pending).
**Invariants tested:** same idempotency key → same offer id (200) · same key different payload → 409 · targeting XOR (CHECK) · price > 0, published ≥ price, valid_until > publish_at (CHECK) · the ingest mirrors those CHECKs and refuses with 400 VALIDATION, storing nothing: an amount outside numeric(10,2), a route that is not three letters or goes nowhere, a currency that is not three letters (stored upper-case), a validUntil not after now and the publishAt (checked only for a new offer: a retry of a stored one still replays), a mediaUrl that is not https, a targetMemberId that is not a UUID; a CHECK it does not mirror (23514) or a value out of range (22003) is a 400 too, never a 500 the CRM retries · a rating from 1.0 to 5.0 (CHECK), refused by the ingest outside it or past one decimal place, and compared on a retry like every stored field · feed visibility = active ∧ published (publish_at ≤ now: a later one is a schedule, in no feed, no Home and 404 by id until then) ∧ valid ∧ (broadcast ∨ mine ∨ my segment) · expire publishes exactly once.
