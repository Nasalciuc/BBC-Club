# domain/requests

**Owns:** schema `requests.*` — `requests` (member fare/offer requests), `request_events` (status timeline).
**Publishes:** `request.submitted` (same tx as insert), `request.status_changed` (CRM webhook). A webhook's `note` is shown to the member under the current step of the request's timeline — written for the member, never for colleagues.
**Consumes:** `request.submitted` → `requests.onRequestSubmitted` (records that the row is ready to send; no network). The partner call lives in `send-requests`. `member.deleted` → redact contact fields, null `member_id`, close the row (operator may still have a CRM lead).
**Ports:** `crm.submitRequest(payload) → { crmRequestId }`; `catalog.indicativeFor(route, cabin)` — the estimate a quote's search showed, asked only when the app says it showed one (`estimateShown`), before the insert, never fatal (an error, a timeout over 1 s or an invalid amount counts `bbc_request_estimates_unavailable{reason}`; ADR-IMPL-042); `catalog.getAirports(codes)` — the destination's city, one batched read per answer, never fatal (`bbc_request_cities_unavailable`, log `request cities unavailable`).
**Facade:** `listForMember` (requests in progress first, newest first), `get`.
**View (`toRequestVM`, internal):** `route` is the outbound leg and `dates` the frames' `Oct 12–19` (`@bbc/shared/requests/display`, shared with the app); `city`, `tripType` and `phone` (the number the specialist calls) for the titles and the detail. The member's state: what the CRM or an operator set; otherwise `received` while the request waits for `send-requests`, `not_sent` after six failed attempts or 45 minutes.
**Jobs:** `send-requests` — each minute; a failure is tried again five minutes later (`SEND_RETRY_MINUTES`), six times (`MAX_SEND_ATTEMPTS`; its claim reads `requests_unsent`); giving up logs an error, counts `bbc_request_sends_given_up` and posts to `OPS_WEBHOOK` (RUNBOOK, "A request that was never sent"). A row it cannot read counts as a failed attempt; a closed row is never sent.
**Out of scope:** catalog/fares, campaigns, respond-to-offer (deleted — one request path only).
**Invariants tested:** Idempotency-Key → one row · another member reusing the key → 409 · IDOR → 404 · ownership in WHERE · send-requests stops after six · CRM mock records payload. Estimate (ADR-IMPL-042): only on a quote whose app showed one, recomputed by the server (a price in the body is dropped), the search's own number with its rules' fingerprint, none beside published fares or outside North America, none on a replay or a rate-limited request; an error, a timeout or a bad amount never refuses a request · the member's note reaches the specialist, quoted · route = the outbound leg, never origin → origin · a city that cannot be read is no city · a new request reads `received`, `not_sent` once the job gives up · the note is redacted on `member.deleted` and a closed row is not sent.
