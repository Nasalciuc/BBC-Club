# domain/catalog

**Owns:** schema `catalog.*` — `fares` (route/cabin/price catalogue), `airports` (IATA reference for pins + autocomplete), `demand_daily` (UTC-day search counts, no member id), and `place_photos` (the photo shown for each airport's city: addresses and credit, or a satellite view's centre — never an image; ADR-IMPL-043).
**Publishes:** none on the journal. When `catalog.search_events` is on and `KAFKA_BROKERS` is set, `GET /v1/search` notes a route event that a flusher publishes to `bbc.search.v1`.
**Consumes:** `bbc.search.v1` on the worker (`APP_ROLE` not `api`), group `catalog.demand`, idempotent via `platform.kafka_processed`.
**Ports:** none (`needs: []`). Repository surface is the port — a Sabre / company-API adapter can replace `fares.repo` later without route changes. Outside calls: the `resolve-place-photos` job asks Wikidata, Wikimedia Commons and (with `PEXELS_API_KEY`) Pexels; `catalogModule({ fetch })` lets tests answer for them.
**Facade:** `searchFares` (at most 30), `getFare`, `destinations`, `searchAirports`, `getAirport`, `getAirports`, `indicativeFor` (the estimate an undated search shows for a route, or null — requests asks it for a quote, ADR-IMPL-042), `importCsv`.
**Routes:** `GET /v1/search` (rate rule `search`), `GET /v1/fares/:id` (410 if past `valid_until` or unpublished, rate rule `read`), `GET /v1/airports?q=` (max 8, rate rule `read`), `GET /v1/airports/popular?from=` and `GET /v1/airports/home-suggestion?tz=` (rate rule `read`), `GET /v1/places/photos?codes=` (1–20 IATA codes, rate rule `read`), `POST /v1/internal/catalog/import` (`catalog:import`), `PUT` and `DELETE /v1/internal/places/:code/photo` (`catalog:import`), `GET /v1/internal/demand?days=7` (`ops:read`, no rate limit).
**Jobs:** `expire-fares` every 15 minutes — sets `published = false` where `valid_until < now()`, then clears the destinations cache. `demand-rollup` at 03:15 UTC writes yesterday's sketches into `demand_daily`. `resolve-place-photos` every minute — up to ten due cities (ADR-IMPL-043).
**Home map:** `destinations()` is `DISTINCT ON (route_to)` ordered by price. Without Redis, a 60s process cache. With Redis, key `catalog:dest:{generation}:{HOME}` and `INCR catalog:dest:gen` on import and expire-fares, so every home misses without a SCAN. Airports use `catalog:airports:gen` the same way. A fare that expires mid-minute can stay on the map for ≤ 60s; its detail answers 410.
**Estimates:** `GET /v1/search` adds `estimate` (ADR-IMPL-037) when `catalog.estimates` is on and an undated search has no fare in the cabin: the company's formula, with the rules from the flag row `catalog.pricing_rules` (written by `scripts/load-pricing-rules.ts`; never in the repository). Missing or hand-edited rules → no estimate and `bbc_search_estimates_unavailable{reason}`; shown ones count in `bbc_search_estimates_shown{cabin}`. `indicativeFor` applies the same flag, rules, formula and fare rule for a quote request whose app showed the estimate, returns the rules' fingerprint with it, and counts missing or hand-edited rules in `bbc_request_estimates_unavailable{reason}` (the requests module counts what it stores, `bbc_request_estimates_stored{cabin}`); with estimates off, or no valid rules, it reads nothing. A killed catalog still answers it: `catalog.estimates` off is the switch.
**Discovery** (ADR-IMPL-039): `popular` returns at most four destinations from `from` — the routes searched at least 5 times in the last seven UTC days (`demand_daily`, all cabins together), busiest first, then the hubs by `popularity`; never the origin or an airport under 100 km from it. Names only: a count never leaves the server. With Redis, cached 5 minutes under `catalog:popular:{airports gen}:{FROM}`. Until `catalog.search_events` is on and `demand-rollup` has run, it shows the hubs alone. `bbc_popular_destinations_shown{source="searches"|"hubs"}` counts what was shown. `home-suggestion` returns the busiest airport whose `tz` is the phone's zone or that zone's current name (`ZONE_ALIASES`: Android reports ICU names such as `Asia/Calcutta`); `null` for UTC or an offset; 400 when `tz` is not a time zone.
**Place photos** (ADR-IMPL-043): `GET /v1/places/photos` answers from `place_photos` at once — `photo` (a card's and a full-width address, and the credit: author, licence, the photo's page; `club` for an operator's photo, null when it needs none), `satellite` (the point the app centres a Mapbox satellite view on: the city's centre, else the airport) or `none` (not looked up yet: the app shows its own image); an unknown code is left out, and a known airport never asked about gets a `pending` row in the same request (one INSERT … SELECT; on conflict a no-op update returns the row another request added, so it is answered too). `resolve-place-photos` claims up to ten due rows (`FOR UPDATE SKIP LOCKED`, new rows first, a ten-minute hold), asks Wikidata once (P238 → the airport within 50 km of ours → P931 the city: P3451 night view, P18 image, P625 centre) and Commons twice (500 and 1280 px, Wikimedia's standard widths; JPEG, landscape, wider than 1280, free licence, no restrictions, an author when the licence asks), then Pexels for at most three cities (`<city> skyline`, a description naming the city and no person); else the satellite view. A failed source (Commons' HTTP-200 errors included) leaves the row as it was and tries again after `least(attempts, 24)` hours — never a downgrade; a key Pexels refuses (401) counts as none for the run — a photo shown stays, a city without one gets a day of satellite view; every resolved row is looked at again after 30–33 days. An operator's photo (`PUT /v1/internal/places/:code/photo`) never expires and no job write touches it (`source IS DISTINCT FROM 'override'` on each one); `DELETE` hands the city back. Flag `catalog.place_photos` (seeded on) off: the route answers `{ items: [] }` and the job asks nothing. Metrics `bbc_place_photos_resolved{status,source}`, `bbc_place_photos_failed{stage}`, `bbc_place_photos_requested`.
**Out of scope:** promotional offers (`proposals.offers`), Sabre adapter, mobile wiring.
**Invariants tested:** search JFK→LHR business → ≥3 · expired fare → 410 · airports `q=JF` ranks JFK · import idempotent · unauthenticated → 401 · timed fixture `arrive − depart == duration` · fa01 maps to 18:55 / 07:00 / +1 · same clocks under Europe/Chisinau and America/Los_Angeles · every `airports.csv` `tz` is IANA. Search events reject `memberId`, `ip`, and `deviceId`. Estimates: only without fares, never between one metro's airports or for an unconfirmed country, first only above business; the engine reproduces the reference results (`tests/parity`, CI secret). Discovery: searched ≥ 5 times in seven days first, then the hubs · never the origin or its metro · no count in the body · `Asia/Calcutta` → DEL, `Etc/UTC` → none · every airport `tz` is reachable from the name a phone reports. Place photos: a new airport is `none` then a Commons photo with its credit · Pexels only with a key and at most three a run · a source that fails keeps the row and backs off · the job never overwrites an operator's photo · unknown codes are left out · flag off → no photos, no lookups · an item an older app cannot read is dropped, not the answer.
