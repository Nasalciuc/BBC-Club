# core/notifications

**Owns:** schema `notifications.*` — notifications (inbox + push queue: category, status pending/sending/sent/delivered/failed/suppressed, scheduled_for, read_at), device_tokens (platform, native_token, active), campaigns (one per broadcast offer: status pending/running/done, `last_member_id` cursor, UNIQUE source_event_id).
**Publishes:** `notification.delivered`, `notification.failed` (noConsumer; analytics).
**Consumes:** `offer.published` → personal: one row for the target (consent + quiet hours + 1 offer push per server day, UNIQUE member+offer+category); broadcast: one `campaigns` row (UNIQUE source_event_id), nothing else in the delivery · `offer.withdrawn` / `offer.expired` → suppress pending · `request.status_changed` → transactional "Your quote is ready" when `to=quoted` · `member.deleted` → delete tokens + rows.
**Ports:** `PushSender.send(platform, token, payload)` (integration/push), `Members.timezoneOf/getStatus/preferencesOf/audiencePage`.
**Facade:** `inbox(actor)`, `unreadCount(actor)`, `markRead(actor, id)`.
**Jobs:** `campaign-fanout` (every minute, singleton: pages the audience 1 000 members per transaction — one cap query per page, quiet hours per time zone, ON CONFLICT DO NOTHING, cursor in `last_member_id`), `dispatch` (poller-style loop: advisory lock via job singleton, SKIP LOCKED 100, ≤20/s, recheck status+prefs at send), `receipts` (sent without delivered > 24 h → receipt_unknown), `cleanup-devices` (inactive 180 d).
**Out of scope:** email/SMS channels, in-app chat, segment fan-out (campaigns; no cross-schema JOIN to offer_targets).
**Invariants tested:** dedupe by unique index · broadcast delivery writes one campaign and zero notifications · a campaign resumes after a crash without duplicates · withdrawn offer → suppressed · dead token deactivated on Unregistered/BadDeviceToken · quiet hours with member timezone · transactional bypasses consent and quiet hours · mark-read is scoped (foreign row → 0) · payload contains no PII.
