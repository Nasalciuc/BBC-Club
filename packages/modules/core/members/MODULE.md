# core/members

**Owns:** schema `members.*` — profile (member_id = auth user id, crm_client_id opaque, status active/waitlist/deleted, timezone, preferences, avatar_url), notification_preferences.
**Photo** (ADR-IMPL-056, 0033): `profile.avatar_url` is the member's photo as Explore's greeting (02) and Profile (12) show it — the https address of an image hosted elsewhere, never the image (CHECK `avatar_url ~ '^https://'`); null, and the app shows the member's initials, until one is added. Stored and read only: no route writes it yet (an upload needs a native image picker, ADR-IMPL-055 §7), `PATCH /v1/profile` does not take it, and it goes with the profile on `member.deleted`. `getProfile` and `ProfileVM.avatarUrl` carry it.
**Profile writes** (ADR-IMPL-058): `PATCH /v1/profile` and `PUT /v1/profile/travel` answer the `ProfileVM` that `GET /v1/profile` answers (email and notifications included). What the contracts (`ProfilePatchBody`, `TravelPreferencesBody`, packages/shared) take: a time zone is a name Intl can read (`isIanaZone`: one unreadable zone stopped every broadcast campaign); a phone is stored in E.164 (default country US; an extension is not kept), so it always passes a request's `contact.phone`; the home airport and each destination are three letters, upper-cased (`/^[A-Za-z]{3}$/`, the request legs' rule), destinations each once in the order sent — whether the airport exists is catalog's answer, which members (core) may not ask; Home answers `home:null` for a code it does not know; a name is trimmed and never blank; no free-text field carries U+0000 or a UTF-16 surrogate without its pair (Postgres would refuse or alter it); travel preferences keep each infant with an adult. Travel preferences merge in one UPDATE (jsonb `||`): keys sent replace, keys not sent stay, two saves at once both land.
**On-demand profile row:** right after the join code, before `member.registered` is delivered, a profile write finds no row; when the account still exists (identity's `registeredEmail`, read from `auth.user` and never from the session, which a deleted member's other device keeps in the cookie cache for up to a minute) it makes the row the delivery would make (`ensureProfile`, the same `insertProfile`: CRM match, `members.allow_non_crm_signups`, ON CONFLICT DO NOTHING) and writes once more; an account that is gone gets 404 and no row. It publishes nothing: the delivery then inserts nothing and publishes `member.linked_to_crm` once, from the row it finds.
**Publishes:** `member.linked_to_crm`, `member.profile_updated`.
**Consumes:** `member.registered` → create profile + match crm mirror by normalized email (`active` if matched, `waitlist` if not — ADR-PROD-001; `members.allow_non_crm_signups` stays off in v1); `member.deleted` → hard-delete profile + preferences. Not registered yet (stage 1): `crm.mirror.synced` → link waitlist members whose email appeared.
**Ports:** `CrmLookup.findByEmail` (integration/crm); identity's `listUsersCreatedBefore` (reconcile) and `registeredEmail` (the on-demand row).
**Facade:** `getProfile(actor)`, `updateProfile(actor, patch)`, `setTravelPreferences(actor, patch)` (merged, never replaced), `setNotificationPreferences(actor, prefs)` (opt-outs; transactional cannot be turned off), `ensureProfile(memberId, emailNormalized, deps)` (the profile row before `member.registered` is delivered; publishes nothing), `getStatus(memberId)`, `timezoneOf(memberId)`, `activeMemberIds()`, `audiencePage({ category, after, limit })` (campaign fan-out: active members who accept the category, keyset on member id, one query per page), `preferencesOf(memberId)` (for notifications dispatch).
**Jobs:** `reconcile-profiles` (every 15 minutes, `*/15 * * * *`, singleton: auth users older than 5 minutes without a profile → re-emit member.registered). No purge job: deletion is a hard delete through `member.deleted`, and nothing sets status `deleted`.
**Out of scope:** tiers/loyalty levels (field reserved), operator edits (v2).
**Invariants tested:** registered→profile exactly once (duplicate delivery → one row) · a write before the delivery makes that one row, and the delivery links to the CRM once, from the row · linked ⇔ crm_client_id present (CHECK) · a photo is an https address or none (CHECK), read by the profile, never written by a profile patch · transactional preference cannot be disabled (CHECK) · two concurrent travel saves both land · delete cascade zero rows, and a save from a session that outlived the deleted account makes none again · reconcile re-emits only when profile missing.
