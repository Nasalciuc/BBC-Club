# platform

**Owns:** schema `platform.*` — `domain_events` (partitioned monthly), `event_deliveries`, `event_dlq`, `external_inbox`, `flags`, `generations`, `job_runs`, `rate_limits`; the SQL API `platform.bump_generation(k)` and `platform.bump_generation_trigger(k)` that other schemas' triggers call (0045).
**Publishes:** nothing. **Consumes:** nothing. It is the mechanism other modules publish and consume _through_.
**Facade (`src/api/index.ts`):** `events.{defineEvent, registerConsumer, publish, tombstoneMember}` · `flags` · `rateLimit.{rule, check}` · `jobs` · `poller` (host only) · `logger` · `metrics` · `reference.{generations, snapshot, memo}` · `cache` · `search` · `streams` · `kafka` · `redis` · `health()` · `close()`. `@bbc/platform/ratelimit` also exports `routeGate`.

**Reference data (ADR-IMPL-075):** a statement-level trigger on each reference table bumps its row of `platform.generations` in the writing statement (`platform.flags`, `catalog.airports`, `catalog.fares`, `catalog.site`, `proposals.offers`). Each process reads the counters at most once a second (`reference.generations`, 500 ms read timeout, the last counters kept when Postgres does not answer; `staleMs()`, `invalidate()`). `reference.snapshot(key, load, { maxAgeMs })` holds a whole table until its generation moves and serves it while Postgres is away; `reference.memo(keys, { maxEntries, ttlMs })` keeps results keyed by request for one generation of each table. Both count `cache_hit`/`cache_miss` by `ns`.

**Route gate (ADR-IMPL-075):** `routeGate(platform, owner).on(routes, "/v1")` declares a route once — the path, then `{ permission, rate, rateBy, reads }` — and checks every route in one order: the rate rule, the permission, the kill flags of the owner and of every module in `reads`; it writes the route registry the inventory tests read. `rateBy: "route"` registers a rule a later step of the route counts.
**Guarantees:** event + deliveries written in the caller's transaction (atomic with the state change) · at-least-once delivery · handler writes and delivery status commit together · 6 retries with exponential backoff then DLQ · consumer pause without deploy. The Kafka relay `platform.kafkaRelay` is registered only when `KAFKA_BROKERS` is set. It is at-least-once and does not keep per-aggregate order; consumers are idempotent and order-independent. Ordered delivery is the later Debezium step (ADR-030).
**Does not guarantee:** global ordering · exactly-once for external side effects (handlers must be idempotent) · delivery while a consumer is paused · Redis or Kafka being up. Both are optional. Unset `REDIS_URL` and `KAFKA_BROKERS` leave every path on Postgres.
**Handler timeout:** the poller stops _waiting_ when `handlerTimeoutMs` elapses and rejects the delivery race; the handler must check `ctx.signal.aborted` before each expensive step to stop _working_ on the rolled-back transaction.
**Jobs owned:** `partitions`, `retention`, `queue-health`, `db-observe` (gauges + `OPS_WEBHOOK` thresholds), `db-report` (weekly; also `GET /v1/internal/db-report`). `retention` (ADR-IMPL-077) deletes in batches of 5 000 (`deleteInBatches` from `@bbc/db/helpers`, which stops before the next batch once the job's time is up — its `signal`; every module's retention job passes it): done deliveries after 30 days, dead letters after 90, `kafka_processed` after 14, job runs after 30 days but each job's last run and last finished run (a failure followed only by skipped or running runs stays on `/status`; two statements, each on `job_runs_job_started`), the rate-limit rows as before; the journal's partitions after 24 months, in a transaction that waits 3 s at most for the journal's lock (`SET LOCAL lock_timeout`): past it (55P03) the drop is left for the next day (`partitionsDeferred: 1`, a warning) and the rest runs, so a long read never holds the event inserts behind a queued drop (X8). `partitions` makes the next three months the same way (3 s at most for the lock, `partitionsDeferred: 1` past it, again the next day), and both run in UTC (`SET LOCAL TimeZone`): the SQL functions cut months in the session's time zone, and a session in New York left five hours between two months' partitions that no event could be written into (X7). `jobs.lastRuns()` / `lastFinishedRuns()` read one index probe per registered job (`lastRunsSql`), never a sort of `job_runs`. `publish` writes the deliveries with the event's key the insert returned (`occurred_at` as text, to the microsecond) and reads nothing back from the journal.
**Metrics (ADR-IMPL-073):** `/metrics` is Prometheus text that VictoriaMetrics scrapes: each family once with its `# TYPE` line, every histogram closed by `+Inf`, label values escaped. Every process reports its CPU seconds, memory and event-loop delay (`registerProcessMetrics`). The queue's three gauges, which read the journal at each scrape, are registered only where the poller runs (`queueGauges`: the worker, or `all`). `db-observe` adds PgBouncer's pools and totals (`SHOW POOLS`, `SHOW STATS`: parses and binds show whether prepared statements are reused) and the database's `pg_stat_statements` totals, as counters (`setCounter`).
**Invariants tested:** rollback → no event · one delivery per consumer · single delivery under two pollers · handler rollback + backoff · DLQ after 7 attempts · replay · per-aggregate order · upcast · pause/resume · abortable timeout · tombstone · job singleton/record/failure · flags fail-safe · flags snapshot: 100 reads cost 2 statements, a psql write seen within a second, kill fail-closed after 10 s (`flags-ttl.test.ts`) · generations: triggers bump once per statement, rollback leaves them, once-a-second reads, snapshots and memos (`generations.test.ts`) · the route gate's order and registry (`route-gate.test.ts`) · metrics render (one block per family, `+Inf`, escaped labels; process metrics; no queue gauges without the poller) · a failed query's parameters never in `job_runs.error`, a delivery's `last_error` or a log line (`errorForLog`/`errorLine` from `@bbc/db`).
**Alerts:** oldest pending delivery > 5 min (transactional path) · any DLQ row · job without a successful run in 36 h.

Read and search rate limits use Redis GCRA when `REDIS_URL` is set and fall back to the in-process store on error. Postgres rules are unchanged. `rateLimit.rule(name)` resolves a rule (its defaults, or the cached flag row `ratelimit.<rule>`, read on the pool); `rateLimit.check(rule, subject, exec?)` counts it — by name outside a transaction, or, inside the caller's transaction (`exec`, postgres store), only with a rule resolved before that transaction opened: a flag read inside it would wait for a second pooled connection while holding one (ADR-IMPL-071). Flags (ADR-IMPL-075) come from one snapshot of `platform.flags` per process, current within a second of any write (its trigger); an ordinary flag that cannot be read takes its default, and a kill or pause flag fails closed — killed, paused — when it cannot be read or the counters are older than `KILL_STALE_MS` (10 s).

Strict reads throw where the ordinary ones fall back: `flags.killState(module)` (the host's boot, which must not take an unreadable flag for a killed module; `isKilled` keeps failing closed per request) and `flags.readStrict(key)` (`/v1/app-config`, which keeps its own last good answer). `jobs.lastFinishedRuns()` is the last succeeded-or-failed run per job, for `/status`'s `failingJobs`.
